# Product Files Structure - Crystal Keepsakes

## File Purpose & Usage

### 📋 Two Product Files (By Design)

```
/src/data/
├── cockpit3d-products.js          ← SOURCE (Cockpit3D API data)
└── final-product-list.js          ← PRODUCTION (Customized products)
```

---

## 1. `cockpit3d-products.js` - SOURCE FILE

### Purpose:
- **Base product data** from Cockpit3D API
- **Source of truth** for admin panel
- Generated by: `scripts/fetch-cockpit3d-products.js`
- Updated: Periodically from Cockpit3D API

### Used By:
- ✅ **Admin Panel** (`/admin/products`)
  - Loads this as the base dataset
  - Applies customizations from localStorage
  - Generates `final-product-list.js`

### Export:
```javascript
export const cockpit3dProducts = [ /* 47 products */ ]
```

### When to Update:
```bash
# Pull fresh data from Cockpit3D API
node scripts/fetch-cockpit3d-products.js
```

---

## 2. `final-product-list.js` - PRODUCTION FILE

### Purpose:
- **Customized product data** with admin edits
- **Used in production** by frontend
- Generated by: Admin panel "Generate" button
- Contains: Base data + custom images + price overrides + visibility changes

### Used By:
- ✅ **Product Detail Pages** (`ProductDetailClient.tsx`)
- ✅ **Product Listing** (`/products`)
- ✅ **Static Generation** (`products/[slug]/page.tsx`)
- ✅ **All Frontend Components**

### Export:
```javascript
export const finalProductList = [ /* 47 products with customizations */ ]
```

### When to Update:
1. Open admin panel: `/admin/products`
2. Make changes (images, prices, visibility)
3. Click "Generate final-product-list.js"
4. Download replaces `/src/data/final-product-list.js`
5. Commit and deploy

## Key Points

### ✅ DO:
- Use `cockpit3d-products.js` in **admin panel only**
- Use `final-product-list.js` in **all frontend components**
- Generate new `final-product-list.js` after admin changes
- Commit `final-product-list.js` to git (it's the production data)

### ❌ DON'T:
- Don't use `cockpit3d-products.js` in frontend components
- Don't manually edit `final-product-list.js` (it's auto-generated)
- Don't delete either file (both are needed)
- Don't import both in the same component

## File Imports Reference

### Admin Panel:
```typescript
// ✅ CORRECT - Admin uses source data
import { cockpit3dProducts } from '@/data/cockpit3d-products';
```

### Frontend Components:
```typescript
// ✅ CORRECT - Frontend uses customized data
import { finalProductList } from '@/data/final-product-list';

// Or with aliasing:
const { finalProductList: products } = await import('@/data/final-product-list.js');
```

## Why Two Files?

### Single Source of Truth Problem:
If we only had one file:
- ❌ Admin edits would overwrite Cockpit3D updates
- ❌ Cockpit3D updates would erase admin customizations
- ❌ No way to "reset" to base data
- ❌ Hard to track what was customized

### Two File Solution:
- ✅ Base data separate from customizations
- ✅ Can refresh from Cockpit3D without losing edits
- ✅ Admin panel merges both: `base + customizations = final`
- ✅ Clear separation of concerns

## Troubleshooting

### Products not showing customizations?
- Check frontend is importing `final-product-list.js` not `cockpit3d-products.js`
- Verify `final-product-list.js` was regenerated after admin changes
- Clear browser cache after deploying new file

### Admin panel shows wrong data?
- Make sure admin imports `cockpit3d-products.js`
- Check localStorage for stuck customizations
- Refresh page to reload from file

### Lost customizations after Cockpit3D update?
- This is expected! `cockpit3d-products.js` overwrites base data
- Your customizations are in localStorage (until you generate final file)
- Always generate `final-product-list.js` before updating from Cockpit3D
